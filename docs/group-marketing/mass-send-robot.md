# 机器人群发

向账号已加入的、带 `@username` 的群组/超级群发送**随机拼接的 @Bot 文本**（非 Bot API 发消息）。

## 前置条件

* `账号/` 内有已登录 session
* `botconfig.txt` 非空（每行一个 @Bot 用户名,同时后端需登录此文件中的机器人）
* 建议准备 `广告.txt`（用于 `log/群发日志记录/` 分文件命名）

## 启动流程

1. 主菜单 → `2.群发` → `1.机器人群发`
2. 按提示输入：
   * **群发间隔（秒）**：默认 40，建议 90～180 降低双向风险
   * **每账号发送多少轮后重启**：0 = 不限制
   * **群组列表多少轮刷新一次**：默认 100

账号加载数量上限 **MaxCount** 由授权服务端下发（默认 50），启动时不在此步骤询问。

## 发送逻辑

1. 拉取账号已加群列表（带 username 的 megagroup / chat）
2. 每群：从 `botconfig.txt` 随机抽最多 3 条拼成正文
3. 正文前加 **6～10 位随机字母数字 + 空格**（避免内容完全一致）
4. 发送后尝试删除消息（降低群内残留）
5. 群与群之间等待「群发间隔」秒

## 异常与归档

| 情况 | 处理 |
|------|------|
| `UserBannedInChannelError` | 先 @SpamBot 验证；仅单群受限则剔除该群，确认双向则移入 `双向限制账号/` |
| FloodWait | 等待后重试或跳过（视秒数） |
| 慢速模式 | 记录到 `log/慢速模式群组.txt`，跳过 |
| 无可发群 | 移入 `无群组账号/` |

## 日志

* `log/群发日志记录/` — 按 `广告.txt` 各行末段（或 `----` 前段）分文件
* `log/账号下线日志.txt` — 账号停止原因
* `双向限制账号.txt`（程序根目录）— 待搬运清单（后台线程兜底）
* `无用账号.txt`（程序根目录）— 待移入异常账号（兜底）
